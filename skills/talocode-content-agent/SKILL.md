# talocode-content-agent

Create original, evidence-led Talocode and TeraAI content through a repeatable brief-to-improvement loop.

## Purpose

Turn a specific audience problem into a useful, original social asset with visible proof, human approval, and a performance receipt that improves the next run.

## When to Use

Use this skill when:

- Planning a Talocode product Short, demo, post, or thread
- Planning useful TeraAI learning content
- Adapting a proven content pattern into an original Talocode artifact
- Reviewing a draft before publication
- Recording content performance and selecting the next experiment

## Core Loop

Use the leading word **receipt**: every stage leaves a reviewable artifact before the next stage begins.

```text
brief -> draft -> evidence review -> approval -> publish -> performance receipt -> improve next run
```

## Workflow

### 1. Brief

Write one brief for one audience and one problem.

```text
Audience:
Specific failure:
Useful outcome:
Visible proof:
One destination:
Channel lane:
```

Completion criterion: the brief names one real failure and one demonstration that can prove the proposed outcome.

### 2. Draft

Create the master script before adapting it for any platform.

For short-form video:

```text
0-3s: specific failure or result
3-12s: why the usual approach fails
12-45s: visible workflow and evidence
45-60s: outcome and one destination
```

Use natural language, readable captions, and original visuals. Show the product action rather than making broad capability claims.

Completion criterion: the draft has one clear hook, one proof sequence, and one destination.

### 3. Evidence Review

Verify the content before asking for approval.

- Check every technical, product, and performance claim against a real result.
- Confirm the destination works.
- Confirm visual proof matches the words on screen.
- Remove claims that cannot be demonstrated.
- Ensure external names, marks, assets, and references do not appear in public-facing content.

Completion criterion: every claim in the asset has visible proof or is removed.

### 4. Approval

Require human approval for public publishing, product claims, performance claims, paid promotion, and brand-sensitive replies.

Completion criterion: an approved review copy, title, caption, and destination exist before any public upload.

### 5. Publish

Keep content lanes separate.

- Talocode: developer failures, product workflows, build evidence, and open-tool infrastructure.
- TeraAI: learning, recall, revision, and study workflows until broader product access is available.

Publish one Talocode Short per day. Adapt the master asset for each destination without changing the supported claim.

Completion criterion: the published asset has the correct lane, destination, and platform-specific copy.

### 6. Performance Receipt

Review each public asset after at least 72 hours.

```text
Asset:
Date:
Hook:
Audience:
Views:
Average watch percentage:
Early retention:
Shares:
Comments:
Subscribers or followers gained:
Destination traffic:
What worked:
One next change:
```

Completion criterion: select one tested change for the next asset rather than changing several variables at once.

## Final Report Fields

Report every published asset with these fields so the next run improves one tested change:

```text
Asset:
Published at:
Lane (Talocode / TeraAI):
Hook:
Proof sequence:
Destination:
Performance receipt scheduled (date):
```

Completion criterion: the report contains every field above and names one tested change for the next asset.

## Constraints

- Create original scripts, visual systems, and demonstrations.
- Use a real workflow, terminal result, product screen, or evidence artifact as proof.
- Keep one primary destination per asset.
- Keep public Talocode content professional and product-facing.
- Do not automate public publishing without explicit approval.
- Never include secrets, private screens, unsupported metrics, or external brand references in public content.

## Validation Checklist

- [ ] The brief describes one specific audience failure.
- [ ] The hook is understandable in the first three seconds.
- [ ] The content visibly proves its primary claim.
- [ ] Captions are readable on a phone.
- [ ] The title, caption, and destination match the approved asset.
- [ ] The Talocode or TeraAI lane is correct.
- [ ] A human reviewed the public version.
- [ ] A performance receipt is scheduled for at least 72 hours after publishing.
